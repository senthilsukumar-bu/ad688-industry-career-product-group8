Skill Gap Analysis

Purpose

This section compares the tools mentioned in our job-posting data with our team’s current skills and experience. We use this comparison to identify where we already have relevant skills, where we need more practice, and what we should prioritize learning next.

How we made the comparison

We use the tool-mention results from our market baseline and the skill information provided by each team member. Because the structured skills field appeared incomplete, we counted selected tools directly in the job descriptions, counting each tool once per posting.

We keep each person’s reported skill level and supporting experience visible. Information that was not provided is marked as “Not reported” rather than treated as no experience. Our learning priorities consider both how often a tool appears in the current sample and each member’s experience with it.

These results remain provisional while the initial job filtering is reviewed. A tool appearing in a description does not necessarily mean it is required, and our comparison does not measure overall job readiness.

Applying the findings

Our main initial priorities are SQL and Python for members who report limited experience. Dashboard practice can follow, with each member choosing a tool relevant to the roles they are considering.

Senthil’s SQL and Tableau experience can support peer review, while Equeen’s Excel and process-improvement experience can help with checking calculations and interpreting operational results. Each member should produce their own work and be able to explain it.

For job applications, we should compare our evidence with the requirements of individual postings. Existing business, operations, and project experience can support our profiles, but the tool-mention percentages alone cannot establish whether someone is ready for a particular role.
